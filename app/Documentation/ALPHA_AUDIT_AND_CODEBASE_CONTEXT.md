# PART 1: CODEBASE CONTEXT (Agent Handover)

## 1.1 What Reclaim Is

Reclaim is a **React Native / Expo** health-tracking app targeting Android (primary) and iOS. It covers:

- **Mood tracking** — check-ins, history, trends, insights
- **Sleep tracking** — Health Connect / Google Fit / Apple Health integration, hypnograms, consolidation
- **Medication management** — schedules, reminders, adherence tracking, refill reminders
- **Training / exercise** — program planner, guided sessions with sets/reps/rest, autoregulation, offline queue
- **Meditation / mindfulness** — scripted sessions, external sources, auto-start scheduling
- **Insights engine** — context-aware, per-screen AI-driven insights
- **Notifications** — intent-based scheduling, reconciler, training live countdown, categories, actions
- **Analytics** — cross-domain trends (mood, sleep, meds, meditation)
- **Data privacy** — export, delete, compliance

## 1.4 Key Architectural Patterns

### Notification System
- **Intent-based**: Screens/hooks call `setIntent(logicalKey, data)` to declare desired notifications.
- **Reconciler**: `reconcileNotifications()` diffs intents vs. scheduled OS notifications, cancels stale ones, schedules new ones.
- **Types**: MED_REMINDER, MOOD_REMINDER, SLEEP_BEDTIME, SLEEP_CONFIRM, TRAINING_REMINDER, TRAINING_SET, TRAINING_REST, MEDITATION_FIXED, MEDITATION_AFTER_WAKE, HEALTH_TRIGGER, MED_REFILL.
- **Channels** (Android): default, reminder-chime, reminder-silent, mindfulness-health, meditation, training.

### Data Flow
- **Supabase** is the source of truth. Local mirrors (AsyncStorage) for mood entries and med logs.
- **React Query** for server state; Zustand for client state (auth, entries).
- **Offline queues** for training sessions and med dose logging.
- **Sync engine** pushes local data to Supabase on foreground/connectivity change.

### Health Integrations
- **Health Connect** (Android 14+), **Google Fit** (older Android), **Apple Health** (iOS).
- Sleep data: imported via `sleepSyncPipeline`, consolidated by `sleepConsolidation`.
- Wake time detection drives after-wake meditation scheduling and circadian insights.

### Training Engine
- Program planner → session plan → guided session (sets, reps, rest, autoregulation).
- Offline queue + sync for session data.
- Notifications: prep countdown, set notifications with Done/Skip/Edit actions, rest countdown with chronometer.

### Insights Engine
- Context builder gathers mood, sleep, meds, training data.
- Insight engine selects per-screen insights based on data availability and rotation.
- Seen store prevents showing the same insight too frequently.

## 1.5 Key Dependencies

React Native 0.81.5, React 19.1.0, Expo ~54.0.33, @supabase/supabase-js, @tanstack/react-query, zustand, react-native-paper, @shopify/react-native-skia, react-native-reanimated, expo-notifications, expo-updates, @sentry/react-native, react-native-health-connect, react-native-google-fit, react-native-health, date-fns, zod.

# PART 2: ALPHA-READINESS AUDIT

## 2.1 RISKS — Error Handling, Auth, Data Loss, Race Conditions

### 2.1.1 Critical: Auth Calls Without Error Handling

**6+ instances** of `(await supabase.auth.getUser()).data.user` without try/catch:

| File | Pattern | Risk |
|------|---------|------|
| `lib/api.ts:17` | `requireUser()` | If `getUser()` network-fails, unhandled throw |
| `lib/api.ts:29` | `createAlphaFeedbackReport` | Same |
| `lib/dataPrivacy.ts:40,100,213,304` | Multiple export/delete functions | Same |
| `lib/sleepSettings.ts:49` | Settings save | Same |
| `screens/onboarding/PermissionsScreen.tsx:119` | Permission setup | Same |

**Fix**: Wrap all `supabase.auth.getUser()` calls in try/catch; check `!user` before use.

### 2.1.2 Critical: Missing Error Boundaries on Screens

`ScreenErrorBoundary` exists but **no screens are wrapped with it**. If any screen component throws during render, the entire app crashes with no recovery UI.

**Fix**: Wrap each screen in `withScreenErrorBoundary` or use `<ScreenErrorBoundary>` in navigators.

### 2.1.3 High: Race Conditions in useEffect (10+ instances)

Many `useEffect` hooks run async operations without cancellation checks:

| File | Lines | Issue |
|------|-------|-------|
| `Dashboard.tsx` | 232-276 | `.then()` chains don't check mounted after await |
| `MoodScreen.tsx` | 700-705 | No cancellation check |
| `RootNavigator.tsx` | 124-172, 175-244 | No cancellation check |
| `TrainingSessionView.tsx` | 177-193, 519-564 | No cancellation check |
| `SleepScreen.tsx` | 645-659 | Has cancellation but no error handling on the async |

**Fix**: Add `let cancelled = false` / `return () => { cancelled = true }` pattern; check before `setState`.

### 2.1.4 High: Empty Catch Blocks (30+ instances)

`.catch(() => {})` appears 30+ times across notifications, training, meds, sleep screens. Errors are silently swallowed.

**Fix**: Replace with `.catch(e => { if (__DEV__) logger.debug('...', e); })` at minimum.

### 2.1.5 Medium: Unsafe Array Mapping

`lib/api.ts:1418-1435` — `.map()` on arrays that may contain null elements without filtering.

**Fix**: Add `.filter(Boolean)` before `.map()`.

## 2.4 SECURITY

### 2.4.1 Critical

- **Hardcoded Google OAuth Client ID** in `app.config.ts:69` as fallback. If `.env` is missing, this is exposed. **Fix**: Remove fallback; fail fast if env var missing.
- **`.env` not in `.gitignore`** (only `.env.local` is). **Fix**: Add `.env` to `.gitignore`.

### 2.4.2 Medium

- **Large Supabase sessions** fall back to AsyncStorage (unencrypted) when they exceed SecureStore's 1900-byte limit (`supabase.ts:37-81`). **Fix**: Consider splitting/compressing tokens or encrypting the fallback.
- **`READ_EXTERNAL_STORAGE` / `WRITE_EXTERNAL_STORAGE`** in AndroidManifest.xml may be overly broad for Android 10+. **Fix**: Review if scoped storage suffices.

### 2.4.3 Good Practices Found

- Supabase RLS: all queries filter by `user_id`.
- Parameterized queries prevent SQL injection.
- Auth tokens stored in SecureStore (primary).
- Sentry auth token uses environment variable, not hardcoded.

## 2.6 OFFLINE & NETWORK RESILIENCE

### 2.6.1 What Works

- **Training sessions**: offline queue + sync on reconnect.
- **Med dose logging**: offline queue (`MedDoseOfflineQueue.ts`).
- **Network status**: `useNetworkStatus` hook + `NetworkStatusIndicator` banner.
- **Sync engine**: `withRetry()` (2 retries, 500ms delay).

### 2.6.2 Gaps

- **Most `api.ts` functions** have no retry logic — Supabase calls fail immediately.
- **No exponential backoff** — all retries use fixed delays.
- **No circuit breaker** for repeated failures.
- **No query timeouts** — app may hang on slow Supabase queries.
- **Sleep/health data** has no offline queue — sync fails silently if offline.
- **Mood entries** use AsyncStorage mirror but no explicit offline queue for new entries.

## 2.9 ADDITIONAL AUDIT AREAS

### 2.9.1 Deep Link Security

- Deep links (`reclaim://`) are unvalidated — any app can send `reclaim://meditation?autoStart=true`. The app should validate deep link sources or at minimum ensure auto-start doesn't do anything harmful without user confirmation.

### 2.9.2 Data Migration / Schema Evolution

- No visible migration system for AsyncStorage data. If data shapes change between versions, existing users may hit crashes or data loss.
- **Fix**: Add versioned storage keys and migration logic.

### 2.9.3 Memory Leaks

- Large screens (Dashboard, SleepScreen, TrainingSessionView) with many `useEffect` subscriptions and timers. Verify all return cleanup functions.
- `setInterval` in AuthProvider (30-minute refresh) — cleaned up, but verify edge cases on session changes.

### 2.9.4 Concurrency

- `reconcileNotifications()` can be called from multiple places (hooks, sync, settings changes). No mutex/lock — concurrent calls could schedule duplicate notifications.
- **Fix**: Add a simple queue or lock to `reconcileNotifications()`.

### 2.9.5 App Startup Time

- `RootNavigator` does: auth check → onboarding check (local + remote) → startup sync → health sync. This is sequential. If Supabase is slow, splash screen may persist for 12+ seconds (failsafe timer).
- **Fix**: Parallelize independent checks; reduce failsafe timeout; cache last-known state.

## 5.2 Product / UX direction (ChatGPT brainstorm + your alignment)

**North star:** Every main screen should answer **State → Meaning → Action**, not “state → more state → settings → admin.”

**Screen priority (ChatGPT order)** for premium polish: **Home** first, then **Medications**, **Mood**, **Sleep**, **Mindfulness/Meditation**—with role clarity (mindfulness = quick regulation; meditation = longer guided).

**Home (Dashboard) target:**

- **Daily state / prediction** — One clear read: how am I doing, what’s limiting, how urgent (human-supportive copy).
- **Top priority** — One actionable recommendation with clear CTAs (conceptually: accept / adjust / why).
- **Today plan** — Compact schedule; routine intents should use **anchor times**, not “app open time”; show more/less for length.
- **Supporting modules** — Mood, exercise, sleep, **one** insight-style block where it fits; **compact** lifecycle hero / brain (not dominating the first fold).

**Tiles vs cards (current direction):** Use **compact informational tiles** (e.g. side-by-side) where it saves vertical space; use **action cards** for primary CTAs. Dashboard already has a **row of two tiles**: **Prediction engine** (12h rules-based forecast from sleep/med/mood signals; confidence; drivers; modal on tap) and **Sleep** (last night headline, range, hypnogram-style background chart, stages label; tap → sleep detail/modal/screen).

**Premium tile spec (still in progress):**

- One **dominant headline** per tile; avoid duplicating tags/labels across tiles and Sleep screen.
- Clear **reading zone** vs **contextual background** (trajectory curve for forecast; real **stage-segment hypnogram** for sleep—not a generic bar chart).
- **Subtle motion** tied to meaning (e.g. stability vs volatility); **tap affordance** for details.
- Remove decorative noise; backgrounds should be **meaningful**, not random circles.

**Theming:** Neumorphic / soft-elevated surfaces live in shared UI—**`AppCard`**, **`Button`**, MD3 theme **`elevation`** overrides (`theme/index.ts`) so elevated surfaces stay on-brand (blue/dark), not MD3 purple tints. Cards use **solid** fills for the raised look; avoid accidental transparent children fighting Skia/backdrops.
