# R04 — Versioned weekly requirements and daily allocation

**Type:** integration task. **Depends on:** R03's committed eligibility contract. **EIF:** N-0069. **Current tree:** `weeklyProgramme.ts`, `weeklyProgrammeTypes.ts`, `programPlanner.ts`, `buildProgramDaySession.ts`, `engine/index.ts` and `balancedHypertrophy.ts` have uncommitted partial edits. Validate the diff before altering it.

**Objective and scope.** Make the weekly programme determine requirements and distribute work across selected days before a daily prescription is built. Use a stable strategy ID and policy version, never English display text, while retaining `buildFourWeekPlan` as the sole calendar writer and `buildProgramDaySession` as the product session entry. Own the weekly compiler/types and the minimal planner/engine/day-adapter changes. Existing numeric doses are policy inputs, not new scientific truth.

**Why.** [Audit R1/R2/R9](../../../../.eif/audit/training-intelligence-20261012/PROJECT_AUDIT_REPORT.md) and [training T01/T02/T08](../../../../.eif/audit/training-intelligence-20261012/training/REPORT.md): exact labels choose a second prescription path; five floor-only days can be empty; hybrid two/three days can contain no run. One calendar writer has not meant one prescription policy.

**Required behavior and acceptance.** Define required weekly exposures/sets from the current approved policy **before** choosing day exercises; allocate to eligible day slots under existing caps and trace each day back to the weekly requirement. Repeated labels, translations or trailing spaces leave prescription unchanged. No feasible candidate or authorized hybrid run placement yields an explicit unmet requirement/infeasibility, not valid-looking silent omission. Preserve saved/started session snapshots. Where once-frequency/fat/fitter policy is unresolved, keep accepted legacy behavior with a truthful policy-status flag; do not disable all modes or invent rules. Do not silently change the accepted rack exception.

**Verification/evidence.** Focused real-planner-to-session tests across 2–6 selected days, goals/modes, equipment, restrictions and weeks, including the Phase 1 five-day fixture and a label metamorphic test. Assert *week-level requirements precede and constrain* day output; a daily-template aggregate alone fails acceptance. Run required AGENTS gates and independent algorithm/architecture review. Save full plans, unmet reasons and policy/version hashes; stage explicit owned paths, commit/push and add evidence toward N-0069.

**Exclusions/completion.** R05 owns independent validation; R09 owns UI/persistence projections; no new periodization, hypertrophy constants, run placement policy, schema migration or live data. Complete when the compiler's weekly contract and supported/infeasible cases are source-validated; N-0069 remains open until R05.
