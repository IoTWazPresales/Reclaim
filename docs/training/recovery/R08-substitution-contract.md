# R08 substitution contract

R08 only; consumes committed R03 exercise eligibility and R06 qualified canonical history. This is a source checkpoint contract, not N-0070 acceptance.

Candidates come from actual catalogue entries. Ranked alternatives retain precedence, then other eligible matching-intent entries are considered. The same R03 equipment, injury, forbidden-movement, dislike and slot skill gates run before candidates are displayed and again at confirmation. The current saved training profile is fetched for the dialog and freshly read at confirmation; a missing/failed read fails closed. Existing sessions do not require a new planning snapshot.

Replacement keeps the frozen slot set count/indices. Repetition or duration targets and rest use the existing engine helpers and exercise overrides from `rules.v1.json` / `docs/training/ROUTINE_AUDIT.md`; no scientific number or threshold is introduced. Its own valid baseline and qualified R06 history are the only load sources. Cross-exercise anchor inference is disabled. Assistance/unsupported units and absent calibration produce an explicit enter-load state; bodyweight has zero external load. Source exercise kg, reps, warmups and autoregulation overlays are never transferred.

The allowed exception to frozen unperformed work is recorded as `replacementScope: session`, `replacedFrom`, timestamp, original planned blob, load convention and calibration/explanation. Repeated replacement retains the previous record as a nested original snapshot. No programme/day override is written. Completed and partially completed items, skipped/ended work, log rows and pending offline item work cannot be relabelled through the replacement path.

Persistence verifies ownership and the original identity/plan, reads canonical work and local pending work strictly, and compares planned/performed/skip/identity again in its item update. UI cache publication follows successful persistence; a failed write leaves the old identity. Old adjustment overlays are cleared on successful replacement. `applySetCompletion` remains the completion authority; a shared per-item runtime lock serializes it with substitution. Existing log writes and performed merges reject an explicit stale exercise identity. New offline Done payloads preserve exercise identity; merge failures retain the operation as blocked. Legacy replay with no exercise identity cannot merge into an item with a replacement record.

The local lock and row comparison do not form a distributed transaction. A log insertion or session end concurrent from another runtime can interleave with replacement; true multi-device atomicity needs an approved database change, outside this task. R08 source tests do not prove that guarantee. An unidentified legacy queued insert may create an unlabelled log row before the performed merge is refused; its queue remains blocked. The legacy guard proves preservation of performed identity, not side-effect-free rejection. Android render and notification/watch journeys remain for R11. EIF evidence/acceptance stays blocked by the existing owner error; N-0070 stays open. No live data was mutated, and no R09 work was started.
